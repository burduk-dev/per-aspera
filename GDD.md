# Per aspera ad asteroid — GDD MVP

**Версия:** 0.2  
**Дата:** 2026-10-03  
**Статус:** рабочий дизайн-документ  
**Платформа:** Web / HTML5  
**Команда:** 1 разработчик  
**Монетизация:** бесплатно  
**Основной фокус:** экономика, логистика и проектирование кораблей

> Обозначения: **Исходное требование** — решение пользователя. **Рекомендация** — предлагаемое решение для MVP, которое можно пересмотреть по результатам тестов.

## 1. Executive Summary

Per aspera ad asteroid — экономическая игра с видом сверху о развитии компании по добыче астероидных ресурсов. Игрок отправляет корабли к астероидам, добывает сырьё, доставляет его на торговые точки с разными ценами и вкладывает прибыль в улучшение и расширение флота. Корабли управляются командами по клику и автоматически выполняют назначенные задачи. Главная особенность — строительство корабля на фиксированной квадратной сетке: игрок выбирает или создаёт форму корпуса из клеток, заполняет корпус отсеками, задаёт уровень каждого отсека и устанавливает совместимые модули. Реактор производит энергию пассивно, остальные рабочие модули потребляют её. MVP проверяет, интересны ли игроку экономика рейсов, выбор рынка и компромиссы между стоимостью, мощностью, вместимостью и эффективностью корабля.

### Столпы игры
1. **Экономические решения:** сравнение цен, расстояний, времени рейса и ожидаемой прибыли.
2. **Корабль как инвестиция:** форма корпуса, отсеки, уровень отсеков и модули влияют на итоговые характеристики и стоимость.
3. **Автоматизированный флот:** игрок задаёт цели и маршруты, а не пилотирует каждую секунду.

### Целевая аудитория
- Игроки, которым нравится оптимизировать производство, торговлю и логистику.
- Игроки, которым нравится собирать машины из модулей и наблюдать последствия инженерных решений.

### Краткие параметры
| Параметр | Решение |
|---|---|
| Жанр | Экономическая стратегия / управление флотом |
| Камера | 2D, вид сверху |
| Визуальный стиль | Пиксель-арт, частицы, простая инерция |
| Платформа | Web, desktop-first |
| Начальный флот | 1 корабль |
| Лимит флота MVP | 3 корабля |
| Игровой мир | Одна небольшая система |
| Основной цикл | Разведать цель → добыть → доставить → продать → реинвестировать |
| Условия поражения | Нет жёсткого проигрыша; возможна медленная экономика |
| Монетизация | Бесплатно, без рекламы и платежей в MVP |

## 2. Обзор игры

### Фантазия игрока
Игрок начинает с маленькой добывающей компании и постепенно строит эффективный флот. Решения на трёх уровнях:
- **Рынок:** что продавать и где цена компенсирует расстояние.
- **Логистика:** куда отправлять корабли и как распределять задачи.
- **Инженерия:** какую форму корпуса, отсеки, уровни и модули использовать.

### Основной игровой цикл
1. Посмотреть карту астероидов и актуальные цены рынков.
2. Выбрать корабль и назначить цель кликом.
3. Дождаться автоматического перелёта и добычи.
4. Доставить груз к торговой точке и продать.
5. Сравнить фактическую прибыль и время рейса.
6. Улучшить отсеки/модули или построить следующий корабль.
7. Повторить цикл с более эффективной конфигурацией.

### Границы MVP
**Входит:**
- одна система, астероиды, торговые точки;
- автоматическое движение по командам;
- добыча, хранилище груза, продажа;
- гибридный рынок с базовыми ценами и динамическим спросом;
- фиксированная квадратная сетка строительства;
- корпуса из клеток, отсеки внутри корпуса, уровни отсеков и совместимые модули;
- энергобаланс, готовые чертежи, свободная сборка в ограниченных рамках;
- до 3 кораблей, локальное сохранение, UI на русском.

**Не входит:**
- бои, пираты, повреждения, аварии;
- расход топлива, экипаж, ремонт и производственные цепочки;
- сюжет, миссии, исследования, мультиплеер, аккаунты;
- произвольный контур корпуса и физическая симуляция каждой детали;
- реклама, покупки, серверная экономика.

### Предлагаемые ограничения
- Все доступные астероиды видны сразу; отдельного сканирования нет.
- Корабли не получают урон от столкновений.
- Топливо не расходуется; логистика ограничена временем полёта и грузоподъёмностью.
- На старте доступны два вида руды и три торговые точки.
- Интерфейс desktop-first; мобильная адаптация — базовая, без отдельной схемы управления в MVP.

## 3. Цели MVP и метрики

### Продуктовая цель
Проверить, образуют ли экономика рейсов и фиксированный модульный конструктор понятную и повторяемую игровую петлю.

### Цели
- Игрок может завершить первый рейс без внешнего руководства.
- Различия цен и расстояний делают выбор рынка значимым.
- Изменение корпуса, отсеков и модулей заметно меняет стоимость и характеристики корабля.
- Игрок может перейти от одного корабля к небольшому флоту.
- Прогресс сохраняется между сессиями.

### Целевые ориентиры плейтестов
| Метрика | Ориентир | Что проверяет |
|---|---:|---|
| Завершение первого рейса | ≥ 80% тестировщиков | Понятность цикла |
| Первая продажа | ≤ 5 минут у большинства | Темп старта |
| Первое улучшение | ≤ 10 минут у большинства | Понятность реинвестирования |
| Осознанное сравнение рынков | ≥ 70% | Значимость цен |
| Успешные сценарии сохранения | 100% | Надёжность |
| Критические ошибки в финальном прогоне | 0 | Готовность билда |

### Готовность MVP
- [ ] Основной цикл работает от команды до продажи.
- [ ] Стартовый корабль может стабильно получать прибыль.
- [ ] Есть минимум две экономически разные конфигурации корабля.
- [ ] Строительство проверяет клетки корпуса, совместимость отсеков и энергобаланс.
- [ ] UI и симуляция используют один расчёт стоимости/дохода.
- [ ] Сохранение восстанавливает деньги, корабли, чертежи, рынок и рейсы.
- [ ] Нет блокирующих ошибок в целевых настольных браузерах.

## 4. Основной геймплей и системы

### 4.1. Карта и астероиды
Астероид — неподвижная точка добычи с типом ресурса, конечным запасом, расстоянием до рынков и коэффициентом добычи. Все астероиды видны с начала игры.

**Acceptance criteria**
- На астероиде отображаются ресурс, остаток и состояние.
- Корабль может получить команду на астероид.
- При исчерпании запаса добыча прекращается, объект получает статус «Истощён».

### 4.2. Движение и команды
Игрок выбирает корабль кликом, затем кликает по цели. Корабль автоматически разгоняется, летит и тормозит. Смена команды отменяет предыдущую задачу. Столкновения не наносят урон.

Состояния корабля: **Ожидает → Летит к астероиду → Добывает → Летит к рынку → Продаёт → Повторяет маршрут / Ожидает**.

**Acceptance criteria**
- Команда по клику меняет цель и статус корабля.
- Корабль достигает цели без дрожания вокруг точки назначения.
- UI показывает текущую задачу и причину невозможности её выполнить.
- Нельзя начать добычу без подходящего рабочего отсека/модуля или свободного места.

### 4.3. Добыча и груз
Добыча идёт автоматически, если корабль находится в радиусе астероида, имеет работающий добывающий модуль, достаточно энергии и свободную вместимость. Груз абстрактный, без отдельных физических кусков руды.

**Acceptance criteria**
- Добыча ограничена скоростью, вместимостью и запасом астероида.
- При заполнении хранилища добыча останавливается.
- Груз не может превысить вместимость корабля.

### 4.4. Рынок
Гибридная модель: у каждого ресурса есть базовая цена; торговые точки имеют локальный коэффициент спроса; продажа объёма постепенно снижает цену; спрос со временем восстанавливается. Цены обновляются раз в 60 секунд игрового времени.

**Acceptance criteria**
- Игрок сравнивает минимум три предложения по цене и расстоянию.
- Продажа использует цену на момент сделки.
- Продажа списывает груз и начисляет деньги ровно один раз.
- Цена всегда остаётся в заданном диапазоне и не становится отрицательной.

### 4.5. Строительство корабля — фиксированная квадратная сетка
**Исходное требование:** никакого произвольного рисования контура. Корпус состоит из квадратных клеток; отсеки занимают клетки внутри корпуса.

Порядок сборки:
1. Выбрать готовый чертёж или начать новый корпус.
2. Для свободной сборки добавлять/удалять клетки корпуса по сетке, соблюдая ограничения формы.
3. Заполнить клетки корпуса отсеками допустимых типов.
4. Выбрать уровень каждого отсека.
5. Установить в отсек совместимые модули доступного уровня.
6. Проверить итоговые цену, массу/размер, грузовместимость, скорость, добычу и энергобаланс.
7. Подтвердить постройку и списать стоимость.

**Рекомендация MVP:** клетка корпуса может содержать один отсек; отсек занимает одну или несколько клеток только если это требуется конкретным типом. Для первого MVP проще правило «одна клетка корпуса = один отсек». Это следует реализовать как конфигурируемое ограничение, чтобы позднее разрешить многоклеточные отсеки без переписывания всей модели.

Форма корпуса должна быть связной: каждая клетка соединяется стороной хотя бы с одной другой клеткой, кроме одиночного корпуса при редактировании. Ограничить размеры корпуса, например, 4–20 клеток для MVP. Не допускать клеток вне корпуса и перекрывающихся отсеков.

**Acceptance criteria**
- Все позиции привязаны к квадратной сетке; размещение между клетками невозможно.
- Игрок может использовать готовый чертёж или создать форму из клеток в заданном диапазоне.
- Отсеки можно размещать только внутри клеток корпуса.
- Система запрещает несвязную форму, выход за лимиты, наложения и невалидные комбинации.
- Уровень отсека выбирается отдельно от типа отсека.
- Модули можно установить только в совместимый отсек и в пределах его вместимости.
- UI показывает цену и итоговые характеристики до подтверждения.
- Нельзя построить корабль с отрицательным энергобалансом.

### 4.6. Отсеки, уровни и модули
Отсек — функциональная клетка/область корпуса, определяющая, какие модули и уровни доступны внутри. Модуль — конкретное оборудование, установленное в отсек.

**Типы отсеков MVP:**
- **Добывающий:** поддерживает добывающие установки.
- **Грузовой:** поддерживает хранилища.
- **Двигательный:** поддерживает двигатели.
- **Энергетический:** поддерживает реакторы.

**Уровни отсеков MVP:** I и II. Уровень задаёт доступную вместимость/класс оборудования и стоимость отсека. Уровень не должен автоматически давать мощность, если она не описана конфигурацией.

**Модули MVP:** добывающая установка, хранилище, двигатель, реактор; у каждого типа есть варианты I и II.

**Правило расширяемости:** типы отсеков, доступные уровни, допустимые модули, стоимость, требования к размеру и характеристики задаются данными/конфигурацией. После MVP можно добавлять новые отсеки для высоких уровней и дополнительные семейства/типы модулей без изменения основного алгоритма строительства.

**Acceptance criteria**
- Отсек валидирует совместимость устанавливаемого модуля.
- Повышение уровня отсека пересчитывает его цену и набор допустимых модулей.
- Все доступные уровни и совместимости описаны конфигурацией, а не разбросанными условиями в UI.
- Невалидные модули нельзя установить или сохранить в чертеже.

### 4.7. Энергия
Реакторы пассивно генерируют мощность без расхода ресурсов. Все прочие активные модули потребляют энергию. Энергосеть корабля общая, без проводов и распределения по клеткам.

P_net = сумма генерации реакторов − сумма потребления работающих модулей.

**Acceptance criteria**
- UI показывает генерацию, потребление и чистый баланс.
- Корабль с P_net < 0 не проходит проверку постройки.
- Энергия не расходуется со временем.
- Добавление/удаление модуля сразу меняет расчёт.

### 4.8. Флот и автоматизация
Стартовый флот — один корабль, максимум в MVP — три. Корабли имеют независимые задачи, груз и конфигурации. Автоматизация повторяемого рейса может быть включена командой «Повторять маршрут».

**Acceptance criteria**
- Задачи кораблей выполняются параллельно.
- Переключение выбранного корабля не сбрасывает задачи других.
- Заполненное хранилище останавливает добычу; при включённом автопилоте корабль возвращается к выбранному рынку.
- UI показывает задачу, груз, состояние и основные характеристики каждого корабля.

### 4.9. Пауза и скорость
Рекомендация: пауза и скорости 1×/2×. На паузе не обновляются движение, добыча и рынок.

**Acceptance criteria**
- Пауза останавливает игровое время.
- Скорость 2× ускоряет симуляцию, но не меняет формулы результата.
- Результат при одинаковом игровом времени не зависит от FPS.

## 5. User stories и acceptance criteria

| ID | User story | Критерий приёмки |
|---|---|---|
| US-01 | Как новый игрок, я хочу понять первый шаг | На старте видны деньги, корабль, астероиды и подсказка назначения цели |
| US-02 | Я хочу отправить корабль добывать | Корабль летит к астероиду и добывает при выполнении условий |
| US-03 | Я хочу продать груз | При прибытии на рынок начисляется верная сумма, груз списывается один раз |
| US-04 | Я хочу сравнить рынки | Видны цена, расстояние и ожидаемая выручка для текущего груза |
| US-05 | Я хочу модернизировать корабль | Изменение отсеков/модулей пересчитывает характеристики и стоимость |
| US-06 | Я хочу собрать корпус | Клетки корпуса размещаются строго по сетке и проходят проверку связности/лимитов |
| US-07 | Я хочу заполнить корпус отсеками | Отсеки размещаются только в корпусе и соответствуют ограничениям |
| US-08 | Я хочу выбирать уровень отсека и модули | Доступны только совместимые варианты, цена и характеристики обновляются |
| US-09 | Я хочу построить новый корабль | При достаточном капитале корабль создаётся и появляется во флоте |
| US-10 | Я хочу управлять несколькими кораблями | У каждого корабля отдельные задачи, груз и конфигурация |
| US-11 | Я хочу продолжить позже | После перезапуска восстанавливаются деньги, корабли, рынок и состояния |
| US-12 | Я хочу понимать доходность | Отчёт показывает объём, цену, выручку, время и чистый результат рейса |

### Сквозные проверки
- **AC-E1:** выручка = количество × цена; UI и симуляция совпадают.
- **AC-E2:** один груз нельзя продать дважды из-за повторного события или клика.
- **AC-E3:** покупка/постройка не выполняется при недостатке денег.
- **AC-E4:** деньги и груз сохраняются согласованно после сделки.
- **AC-E5:** повторный рейс не создаёт ресурс из ничего; добыча ограничена запасом и временем.
- **AC-E6:** одинаковые состояние, команды и рыночные данные дают одинаковый расчёт.
- **AC-B1:** невозможно разместить отсек за пределами корпуса, вне сетки или поверх другого отсека.
- **AC-B2:** чертёж не может содержать отсутствующий тип отсека или несовместимый модуль.

## 6. Объём MVP и MoSCoW

**Must Have**
- карта, астероиды, движение и команды;
- добыча, груз и истощение;
- три торговых предложения, базовые цены и ограниченный динамический спрос;
- квадратная сетка корпуса, готовые чертежи и ограниченная свободная сборка;
- четыре типа отсеков, два уровня отсеков, четыре семейства модулей с двумя вариантами;
- проверка связности корпуса, совместимости, стоимости и энергобаланса;
- покупка/модернизация, до 3 кораблей;
- основные экраны, локальное сохранение, конфигурация баланса.

**Should Have**
- подсказки первого запуска;
- отчёт о прибыльности рейса;
- автоповтор маршрута;
- пауза и скорость 2×;
- простые частицы двигателя и добычи;
- удобные ошибки конструктора.

**Could Have**
- дополнительные корпуса и чертежи;
- звук интерфейса;
- экспорт/импорт чертежей в локальный файл;
- расширенная статистика флота.

**Won’t Have**
- бои, угрозы, повреждения, ремонт;
- топливо, экипаж, исследования;

## 8. Экономика и формулы

### 8.1. Рыночная цена
p = p_base × demand_multiplier.

Для MVP: demand_multiplier ∈ [0,8; 1,2]. Цена конкретного ресурса зависит от торговой точки и спроса.

После продажи объёма q_s:
m_new = clamp(m_old − α × q_s / Q_market, 0,8, 1,2).

Здесь Q_market — нормирующий объём рынка; α — коэффициент чувствительности. Со временем спрос возвращается к единице:
m_next = m + β × (1 − m) × Δt.

Параметры α и β должны настраиваться в конфигурации. Цены обновляются раз в 60 секунд игрового времени.

### 8.2. Выручка и доходность
Выручка сделки: R = Σ(q_i × p_i).

При отсутствии переменных расходов:
Profit_trip = R − C_variable; в MVP C_variable = 0, если не добавлена отдельная расходная система.

Доходность во времени: Income_rate = Profit_trip / trip_duration.

Не учитывать цену корабля как расход каждого рейса; она учитывается отдельно при анализе окупаемости инвестиций.

### 8.3. Добыча
q_mined = min(rate_effective × Δt, free_capacity, asteroid_remaining).

rate_effective = rate_base × module_multiplier × asteroid_multiplier × power_multiplier.

Рекомендация: обычный ресурс имеет коэффициент астероида 1,0, редкий — 1,25. Если энергобаланс отрицателен, постройка запрещена; в рабочей симуляции модуль работает только при достаточном питании.

### 8.4. Стоимость корпуса и корабля
C_ship = (C_hull + ΣC_compartment + ΣC_module) × k_shape.

C_hull = A × c_cell, где A — число клеток корпуса, c_cell — стоимость клетки. k_shape — коэффициент формы/производственной сложности. Для шаблонных форм коэффициенты задаются вручную; не требуется вычислять сложность произвольного контура.

Пример для настройки: стандартная форма k=1,00; компактная k=1,05; широкая k=1,10; вытянутая k=1,15. Цена каждого отсека зависит от типа и уровня. Стоимость модуля считается отдельно.

### 8.5. Пример стоимости модулей
| Модуль | Цена | Энергия | Эффект |
|---|---:|---:|---|
| Добыча I | 120 | −2 | 1 ед./с |
| Добыча II | 260 | −4 | 1,8 ед./с |
| Хранилище I | 80 | −1 | +30 ед. |
| Хранилище II | 180 | −2 | +70 ед. |
| Двигатель I | 100 | −2 | базовое ускорение |
| Двигатель II | 220 | −4 | повышенное ускорение |
| Реактор I | 140 | +5 | генерация 5 |
| Реактор II | 300 | +10 | генерация 10 |

Стоимость отсеков задаётся отдельной таблицей конфигурации. Пример стартовой цены: уровень I — 50 кредитов; уровень II — 120 кредитов. Эти цены требуют проверки баланса.

### 8.6. Энергобаланс
P_net = ΣP_generation − ΣP_consumption.

Постройка разрешена, если P_net ≥ 0. Энергия не расходуется со временем. Реактор — единственный источник генерации в MVP.

### 8.7. Окупаемость улучшения
Payback_time = Upgrade_cost / (Income_new − Income_old), только если разница доходов положительна.

Доход следует сравнивать на сопоставимом временном отрезке и с учётом полного рейса, включая перелёт и время ожидания.

### 8.8. Баланс и защита от инфляции
- конечные запасы астероидов;
- ограниченная вместимость;
- время полёта и добычи;
- рыночный диапазон ±20%;
- стоимость корпуса, отсеков и модулей;
- лимит 3 корабля для MVP.

Не вводить искусственные расходы на топливо или обслуживание, пока таких систем нет. Если экономика слишком быстро растёт, сначала корректировать цены, время рейса, запасы и производительность.

## 9. Монетизация

Исходное требование — бесплатная игра. Рекомендация для MVP — free-to-play без рекламы, покупок и платных преимуществ. Цель первой версии — проверить игровой цикл.

Критерии:
- весь контент доступен бесплатно;
- прогресс не блокируется рекламой или оплатой;
- интеграция платёжных систем не нужна;
- монетизация рассматривается только после тестирования интереса и удержания.

## 10. Арт, UI/UX и звук

### Визуальное направление
Пиксель-арт, вид сверху, тёмный космос, умеренные частицы, читаемые силуэты. Важнее различимость объектов и характеристик, чем декоративная сложность.

- Карта: звёзды, астероиды, станции, корабли и маршруты.
- Корпуса: клетки сетки читаются при сборке; в игровом режиме сетка может быть скрыта.
- Отсеки: различаются формой/цветом/иконкой типа.
- Уровень отсека: отдельный визуальный индикатор, не единственный способ передачи информации.
- Модули: небольшие пиксельные иконки; характеристики доступны в подсказках.
- Эффекты: двигатель, добыча, выбор цели, продажа.

### Экраны
1. **Карта:** объекты, деньги, выбранный корабль, цель и краткий статус.
2. **Рынок:** ресурс, цена, динамика, расстояние, ожидаемая выручка.
3. **Конструктор:** корпусная сетка, типы отсеков, уровень отсека, слоты/модули, стоимость и характеристики.
4. **Флот:** список кораблей, задачи, груз, доходность и переход к объекту.

### UX-конструктор
Панель сборки должна последовательно вести по этапам: корпус → отсеки → уровни → модули → проверка → постройка. Невалидные действия объясняются сообщением. Ошибки показывают конкретную клетку/отсек, если это возможно.

### Управление
- ЛКМ по кораблю — выбрать.
- ЛКМ по цели — назначить маршрут.
- В конструкторе ЛКМ по клетке — добавить/удалить корпус или выбрать клетку для назначения отсека в зависимости от активного инструмента.
- Вкладки — рынок, конструктор, флот.
- Все важные значения отображаются числами и текстом, не только цветом.

### Звук
Звук необязателен. Можно добавить короткие звуки выбора, покупки, продажи, добычи и двигателя. Музыка не блокирует выпуск.

## 11. Техническая архитектура

### Рекомендуемый стек
Если проект ещё не привязан к технологии: HTML5 + TypeScript + Phaser 3. Допустима Canvas-реализация на TypeScript, если она уже предпочтительна разработчику. Сервер и база данных для MVP не нужны.

### Зафиксированное решение реализации (03.10.2026)
Для первого прототипа выбран нативный HTML5 Canvas + JavaScript ES modules без сторонних библиотек и сборщика. Причина — быстрый запуск через статический сервер и возможность тестировать симуляцию встроенным Node.js test runner без зависимостей. Это осознанный выбор реализации, а не новое игровое требование; перед дальнейшим усложнением конструктора можно повторно оценить необходимость Phaser/TypeScript.

### Принципы
- Экономика и симуляция независимы от рендеринга.
- Все цены, лимиты и коэффициенты вынесены в конфигурацию.
- Симуляция обновляется по игровому времени, а не по кадрам.
- Состояние игры сериализуемо.
- Строительство проверяется централизованным валидатором.
- Данные отсеков/модулей декларативны и расширяемы.

### Предлагаемая структура
- core/: состояние, цикл, команды, конфигурация.
- simulation/: движение, добыча, груз, экономика, рынок, энергия, строительство, флот.
- entities/: корабль, астероид, торговая точка, отсек, модуль.
- builder/: модель сетки, геометрия корпуса, размещение отсеков, валидатор.
- ui/: карта, рынок, конструктор, флот, уведомления.
- persistence/: сохранение, миграции.
- data/: корпуса, отсеки, модули, ресурсы, рынки, астероиды.

### Валидатор строительства
Проверять:
1. Размер корпуса находится в лимите.
2. Все клетки находятся на целочисленных координатах сетки.
3. Корпус связен по сторонам.
4. Отсеки лежат внутри корпуса, не перекрываются и соответствуют правилам размера.
5. Уровень отсека существует.
6. Модули совместимы с типом/уровнем отсека.
7. Вместимость отсека не превышена.
8. Денег достаточно.
9. Энергобаланс не отрицателен.

### Сохранение
Сохранять версию формата, деньги, чертежи, флот, конфигурации корпусов, отсеки и модули, задачи кораблей, грузы, остатки астероидов, рыночные коэффициенты и игровое время. Сохранять после значимых операций и периодически. При ошибочном сохранении показывать безопасное сообщение и не запускать повреждённое состояние без проверки.

### Технические acceptance criteria
- Расчёты симуляции не зависят от FPS.
- При одинаковом состоянии и командах результат воспроизводим.
- Сохранение восстанавливает состояние после перезагрузки.
- Ошибочные данные не ломают игровой цикл.
- В тестовой сцене с 3 кораблями, 8 астероидами и 3 рынками нет заметных задержек.
- Отключение частиц не влияет на правила игры.

## 12. Аналитика и метрики

Для MVP достаточно локального журнала событий и ручного сбора результатов плейтестов. Внешняя аналитика необязательна.

События:
- game_started;
- first_target_selected;
- mining_started;
- cargo_filled;
- sale_completed;
- market_compared;
- compartment_placed;
- compartment_upgraded;
- module_installed;
- ship_built;
- ship_task_changed;
- save_created;
- save_loaded;
- session_ended.

Поля: время события, версия игры, тип ресурса/отсека/модуля, сумма, длительность, состояние корабля. Не собирать персональные данные.

Метрики:
- время до первой продажи и первого улучшения;
- прибыль и длительность рейса;
- доход на игровую минуту;
- распределение выбора рынков;
- популярность типов отсеков и модулей;
- число невалидных попыток сборки и причины;
- время до второго корабля;
- доля сессий, завершившихся до первой продажи.

Аналитика не должна влиять на симуляцию.

## 13. Дорожная карта

### Этап 1 — вертикальный срез (3–4 дня)
- карта, корабль, астероид;
- автоматическое движение;
- добыча, груз, продажа;
- минимальный UI.
**Готово:** можно получить деньги за рейс.

### Этап 2 — рынок и баланс (2–4 дня)
- два ресурса, три торговые точки;
- базовые цены и динамический спрос;
- отчёт о рейсе.
**Готово:** выбор рынка влияет на доход.

### Этап 3 — сеточный конструктор (4–7 дней)
- клетки корпуса и готовые формы;
- связность и лимиты;
- размещение отсеков;
- уровни отсеков и совместимость модулей;
- расчёт цены и энергобаланса.
**Готово:** невалидную сборку нельзя построить.

### Этап 4 — флот (2–3 дня)
- покупка кораблей;
- независимые задачи;
- автоповтор маршрута.
**Готово:** три корабля работают параллельно.

### Этап 5 — UX и сохранение (3–5 дней)
- четыре экрана;
- подсказки;
- локальное сохранение и восстановление.
**Готово:** игру можно закрыть и продолжить без потери состояния.

### Этап 6 — баланс и выпуск (3–5 дней)
- тестирование экономики и конструктора;
- исправление ошибок;
- оптимизация и проверка браузеров.
**Готово:** нет блокирующих дефектов в основном цикле.

Ориентир: 3–5 недель. Если сроки растут, уменьшать количество контента и эффекты, а не ломать основу сеточного конструктора.

## 14. Риски, предположения и открытые вопросы

### Риски
| Риск | Вероятность / влияние | Меры |
|---|---|---|
| Конструктор становится слишком сложным | Высокая / высокая | Ограничить клетки, отсеки и варианты MVP |
| Одна конфигурация доминирует | Высокая / высокая | Балансировать доход на полный цикл, а не отдельные характеристики |
| Игрок не понимает прибыльность маршрута | Средняя / высокая | Показывать цену, расстояние, длительность и ожидаемую выручку |
| Ошибки в клеточной геометрии | Средняя / высокая | Централизованный валидатор и тесты связности/границ |
| Несогласованность UI и симуляции | Средняя / высокая | Общие функции расчёта, тесты транзакций |
| Повреждение сохранения | Средняя / высокая | Версионирование, валидация, безопасная обработка |
| Слишком медленная прогрессия | Средняя / высокая | Плейтестить первый рейс и первую покупку |
| Рынок становится декоративным | Средняя / высокая | Учитывать расстояние и динамику цены одновременно |

### Зафиксированные предположения
- Одна система вместо открытой галактики.
- Нет опасностей и расхода топлива.
- Реакторы не потребляют ресурсы.
- Базовая цена постоянна, спрос динамичен в пределах.
- Корпус строится только на квадратной сетке.
- Отсеки и модули определяются данными/конфигурацией.
- MVP бесплатный, без рекламы и платежей.
- Все числовые значения — стартовые гипотезы для балансировки.

### Открытые вопросы
| Вопрос | Рекомендация MVP |
|---|---|
| Автовозврат при заполнении груза? | Да, если включён повторяемый маршрут |
| Одна клетка — один отсек? | Да для MVP; модель должна позволять расширение |
| Можно ли удалять клетки из середины корпуса? | Только если после удаления корпус остаётся связным |
| Сохранять ли пользовательские чертежи? | Да, локально |
| Должны ли уровни открываться прогрессией? | В MVP оба уровня доступны при наличии денег; будущую разблокировку оставить на потом |
| Мобильный интерфейс? | Адаптивный desktop-first, без отдельной мобильной схемы управления |
| Монетизация после MVP? | Решать после тестирования удержания и интереса |

## Финальные критерии MVP
- [ ] Корабль автоматически летит к цели.
- [ ] Астероид имеет ограниченный запас ресурса.
- [ ] Игрок добывает, доставляет и продаёт груз.
- [ ] Три рынка отличаются ценами и расстояниями.
- [ ] Корпус строится только на квадратной сетке.
- [ ] Форма корпуса проходит проверку связности и размеров.
- [ ] Отсеки заполняют только клетки корпуса.
- [ ] Уровень отсека выбирается отдельно от типа.
- [ ] В отсек устанавливаются только совместимые модули.
- [ ] Цена и энергобаланс рассчитываются до постройки.
- [ ] Можно управлять до 3 кораблей.
- [ ] Сохранение восстанавливает экономику и флот.
- [ ] Основной цикл работает без критических ошибок.
